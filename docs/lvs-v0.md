# LVS 接入层(实例前置接入,进程内实现)

## 背景

实例详情「拓扑结构」把入口画成 `客户端 → LVS · 接入 VIP → Proxy 集群`。
本方案让这条链路真实可用,但不依赖任何第三方镜像:

> 离线/受限网络下无法拉取 haproxy/nginx 等转发镜像,而 rdsctl 运行宿主本身
> 就是 docker daemon 宿主。因此 LVS/VIP 落地为 **rdsctl 进程内 4 层 TCP 转发器**:
> 在宿主 `127.0.0.1:{lvs_mysql_port}` 监听(即实例 VIP),把接入连接轮询转发到
> 该实例**全部 Proxy 容器在宿主发布的端口**(`127.0.0.1:{mysql_port}`,docker 已映射
> 到容器 4051),后端故障自动跳下一个(round-robin)。

## 生命周期

- 创建实例 DAG 在 Proxy 集群启动后执行「启动 LVS 接入(VIP 转发 Proxy 集群)」(
  `Step::EnsureLvs`,幂等):绑定 VIP 端口并注册转发器,随后复制/连通校验经 VIP 验证;
- 实例记录持久化 `lvs = ["127.0.0.1:{lvs_mysql_port}"]`、
  `lvs_container = "rds-{name}-lvs"`(接入层标识)、`lvs_mysql_port`;
- 销毁 DAG 首步 `Step::StopLvs` 关闭转发器(先停接入再停代理/节点/网络);
- **进程重启恢复**:健康巡检(sweeper)每轮对 running/degraded 且登记过接入层的实例
  幂等重建转发器(已存在则跳过),VIP 在服务重启后自动恢复;
- 旧实例(无 `lvs_container`)兼容:连接信息回退直连首代理,无需改造。

## 展示与入口

- 概览「连接信息」入口显示 **LVS 接入 · rds-{name}-lvs**,复制/访问地址用 VIP 端口
  (标注 VIP);拓扑「LVS · VIP」展示真实地址;各 Proxy 端口保留为诊断直连。

## 同机多副本下的归属(重要)

接入层是**宿主机单例**,不是「每副本一份」:监听地址就是本机 `127.0.0.1:{port}`。
而 cluster 模式下**每个副本的巡检都会 `ensure()` 同一实例的同一 VIP 端口**,
必须先回答「谁在持有」,否则会出现两类事故(一类假失败,一类静默错服)。

归属用 `logs/lvs/<port>.owner`(内容=占用者实例名;`RDSCTL_LVS_DIR` 可覆盖)登记,
`ensure()` 遇到 `EADDRINUSE` 时按四条契约裁决:

| 端口状态 | 裁决 |
|---|---|
| 归属=**同一实例**(兄弟副本已接管) | **幂等成功**(debug 日志) |
| 归属=**另一个实例**(典型:已销毁实例的残留转发器) | **报错并点名占用者** |
| 无归属登记,但对端**确实在服务**(能读到数据) | 放行(debug;多为写登记前的竞态) |
| 无归属登记且**不可服务**(被别的进程抢占 / 后端全死的残留) | **报错** |

两条判据不能退化:

1. **不能只看 `connect` 成功**。残留转发器在后端全死时也会 accept,随后关闭连接;
   只看 connect 会把「坏占用」误判成「兄弟副本已接管」,于是**新实例的流量被静默接到
   旧实例的死代理上** —— 比报错更糟。因此要**读到至少 1 字节**才算「在服务」。
2. **不能一律把 `EADDRINUSE` 当成功**。实测事故:创建任务的 `lvs` 节点因兄弟副本先绑定
   而 3 次重试全失败、任务被判失败,而 VIP 一直可用(假失败)。反之若一律放行,则会把
   残留转发器的端口让给新实例(静默错服)。四条契约正是这两者的分界。

**已知残留场景**:`Step::StopLvs` 只在**执行销毁任务的副本**上 `stop()`,
其它副本持有的转发器会留到该副本重启。此时端口在服务但后端已死 →
新实例若分配到同一端口会命中「不可服务 → 报错」并点名占用者(`.owner` 里的实例名),
按提示重启持有它的副本即可释放。彻底解决需按下方 `ingress` 角色口径把绑定入共识日志。

## 边界(后续可演进)

- 接入层为进程内单点(与单进程控制端同生命周期,sweeper 自动恢复);
  生产化可演进为 keepalived 双机 VIP + ipvs,或独立接入网关;
  **演进口径已定**:`RDSCTL_MODE=cluster` 下接入层独立为 `ingress` 角色,路由绑定入
  共识日志(`IngressBind`)、入口以多地址暴露、端口由日志权威分配;承诺口径为
  「多入口地址 + 快速重绑,RTO ≤5s(客户端需重连)」,不承诺单 VIP 无缝漂移。
  详见 [control-plane-ha-design.md](./control-plane-ha-design.md) §10;
- 转发器后端用 Proxy 宿主发布端口(单机 docker lab 语义),跨主机部署时改为
  Proxy 地址列表(字段同构,仅后端地址来源变化)。
